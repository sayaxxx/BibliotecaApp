1 · Resumen

BibliotecaApp es una aplicación web MVC construida con ASP.NET Core (.NET 10), Entity Framework Core y SQL Server LocalDB. Permite administrar:

  • Autores — catálogo con búsqueda por nombre, alta/edición/borrado (módulo refactorizado con ViewModels + servicios).
  • Libros — catálogo con filtro por disponibilidad (Disponible / Prestado).
  • Préstamos — seguimiento con filtro por estado (No devueltos / Devueltos).

Convenciones clave

  • Un préstamo está activo / No devuelto cuando su FechaDevolucion es NULL.
  • Está devuelto cuando tiene la fecha de devolución registrada.
  • Un libro está Prestado si existe algún préstamo activo sobre él.

Para arrancar la aplicación desde la carpeta del proyecto:

# Restaurar dependencias y compilar
dotnet build

# Ejecutar la aplicación (Launch Settings: http profile)
dotnet run

La app queda disponible en http://localhost:5217. Al primer arranque, la aplicación:

  1. Conecta con SQL Server LocalDB usando la cadena de appsettings.json → ConnectionStrings:DefaultConnection.
  2. Crea la base física BibliotecaAppDb.mdf dentro de App_Data\ (AttachDbFilename).
  3. Aplica las migraciones (Database.MigrateAsync()) y siembra datos de ejemplo (DbSeeder).
Nota sobre la base de datos: la aplicación usa una base nueva (BibliotecaAppDb) para no alterar el esquema de la base heredada BibliotecaDb que contenía tablas de un proyecto anterior (Paises, Usuarios, Ejemplares, LibroAutores, etc.).

1 ── N

  • NombreUsuario string
  • FechaPrestamo date
  • FechaDevolucion date nullable

Comportamiento de borrado (ApplicationDbContext)

El borrado en cascada está configurado explícitamente:

RelaciónFKEliminar el padre
Libro → Autor (N:1)Libro.AutorIdBorra sus libros
Prestamo → Libro (N:1)Prestamo.LibroIdBorra sus préstamos
Al eliminar un autor se borran sus libros y, a su vez, los préstamos de esos libros. Las vistas Delete advierten al usuario de este efecto.

5 · Arquitectura en capas (guías HMTL 1–4)

El módulo Autores fue refactorizado para cumplir los requisitos de las guías 1.html–4.html, separando las responsabilidades en tres capas claras:

CapaResponsabilidadComponentes
Presentación Vistas Razor y controladores. Nunca accede a EF directamente. AutoresController, Views/Autores/*
Lógica de negocio / Servicios Reglas del dominio: CRUD de autores, mapeo modelo → ViewModel. IAutorService, AutorService
Datos Acceso a SQL Server con Entity Framework Core. ApplicationDbContext, DbSeeder

El controlador solo depende de la interfaz IAutorService, que se registra en Program.cs con ciclo de vida Scoped. Esto permite probar el módulo con mocks y cambiar la implementación sin tocar el controlador. 

Program.cs
builder.Services.AddScoped<IAutorService, AutorService>();

8 · Vistas y filtros

Todas las vistas están bajo Views/<Controlador>/ y usan el layout compartido Views/Shared/_Layout.cshtml. Los formularios de alta/edición cargan la validación cliente con la parcial _ValidationScriptsPartial.

8.1 · Filtro de libros por estado (Libros/Index)

Un combobox envía por GET el parámetro estado con tres opciones: Todos disponible prestado. La consulta se filtra con LINQ en el controlador: 

LibrosController.Index(string? estado)
// "disponible" => libros sin ningún préstamo activo (FechaDevolucion NULL)
libros = libros.Where(l => !l.Prestamos.Any(p => p.FechaDevolucion == null));

// "prestado"  => libros con al menos un préstamo activo
libros = libros.Where(l => l.Prestamos.Any(p => p.FechaDevolucion == null));

La opción elegida se conserva mediante ViewData["Estado"].

8.2 · Filtro de préstamos por estado (Prestamos/Index)

Mismo patrón que el filtro de libros. Las opciones son: Todos pendiente (No devueltos) devuelto (Devueltos). 

PrestamosController.Index(string? estado)
// "pendiente" => sin fecha de devolución registrada (NULL)
prestamos = prestamos.Where(p => p.FechaDevolucion == null);

// "devuelto"  => con fecha de devolución registrada
prestamos = prestamos.Where(p => p.FechaDevolucion != null);

8.3 · Búsqueda de autores por nombre (Autores/Index)

Un cuadro de texto envía por GET el parámetro buscar; el servicio filtra con Nombre.Contains(buscar) (equivale a un LIKE en SQL).

11 · Seguridad (ASP.NET Core Identity)

La aplicación integra ASP.NET Core Identity para autenticación y autorización basada en roles. Se usan cookies de sesión para mantener al usuario conectado entre páginas.

11.1 · Configuración de Identity

En Program.cs se registra:

  • AddIdentity<ApplicationUser, IdentityRole> con política de contraseña fuerte.
  • AddEntityFrameworkStores<ApplicationDbContext> y AddDefaultTokenProviders.
  • Cookies: LoginPath = /Account/Login, AccessDeniedPath = /Account/AccessDenied, expiración 8 h.

11.2 · Roles y cuentas de prueba

RolPermisosCuentaContraseña
Admin Acceso total: CRUD en Autores, Libros y Préstamos; vista completa de datos. admin@biblioteca.com Admin123!
Bibliotecario Autores (lectura + creación), Libros (CRUD), Préstamos (CRUD completo incluyendo Prestar/Devolver). bibliotecario@biblioteca.com Bibliotecario123!

Reglas de contraseña: mínimo 8 caracteres, al menos una mayúscula, un dígito y un símbolo.
